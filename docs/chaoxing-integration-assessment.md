# 接入学习通（超星）评估报告

> 评估对象：本项目「作业云」与超星学习通 / 泛雅平台的对接可行性
> 结论日期：2026-11-02
> 适用范围：本文结论用于排期与方案选型，**接口细节需以超星商务/技术对接后提供的最终文档为准**

---

## 一、结论速览

**一句话结论：把学习通当"入口 + 身份源"很容易（1～3 周，我方基本可控）；把作业/成绩数据真正双向打通很难（官方没有公开 API，需商务定制，周期不可控）。**

| # | 对接能力 | 难度 | 工期（人天） | 谁必须配合 | 建议 |
| --- | --- | --- | --- | --- | --- |
| L0 | 学习通里放外链，点开进我们的作业系统 | ★☆☆☆☆ | 1～2 | 无 | ✅ 立刻可做 |
| L1 | 单点登录（学习通账号直接进我们系统，免二次登录） | ★★☆☆☆ | 5～8 | 超星（企业账号审核） | ✅ 推荐一期 |
| L1' | 学校统一身份认证 CAS/OAuth2/LDAP 单点登录 | ★★☆☆☆ | 3～5 | 学校信息中心 | ✅ 通常比 L1 更划算 |
| L2 | 班级/学生名单自动同步 | ★★★★☆ | 8～15 | 超星定制 + 商务 | ⚠️ 二期，先用 CSV |
| L3 | 作业题目/提交记录互通 | ★★★★★ | — | 超星定制 | ❌ 官方无 API，暂不做 |
| L4 | 成绩回写学习通成绩册 | ★★★★★ | — | 超星定制 | ❌ 官方无 API，暂不做 |
| L5 | 作业提醒推送到学习通消息 | ★★★☆☆ | 3～5 | 超星（应用审核） | ⭕ 可选二期 |
| L6 | 逆向 cookie 接口强行读作业/成绩 | 技术上 ★★☆☆☆ | 5～10 | 无需（但违规） | ❌ 不建议，见第六节 |

**推荐路线：一期做 L0 + L1（或 L1'）+ CSV 导入导出（约 2～3 周，可交付演示）；二期再谈 L2/L5，L3/L4 明确告知客户"需要超星商务支持"，不作为承诺项。**

## 二、学习通目前到底开放了什么（事实核查）

超星官方的对外开放入口是 **超星微服务开放平台**（`open.chaoxing.com` / 文档站 `auth.open.chaoxing.com`）。

- 官方文档只列出四类能力：
  1. **OAuth 授权认证**（获取 code → access_token → 刷新 token）
  2. **通讯录对接**
  3. **获取用户信息**（含"无角色""无角色、安全"等变体）
  4. **推送功能接入学习通**
- 对接形态有两种：**自建应用**（给某个单位用，用应用链接地址接入，跳转时追加 `code`、`state`、APP ID/KEY）和 **市场应用**（上架应用市场，全网可用）。
- 原先的「路由接口对接」模块文档里明确标注 **"该模块已停用"**。
- 使用企业账号需注册 → 提交审核 → 管理员审核通过后才能拿到 APP ID / APP KEY；个人账号只能用 OAuth 认证。
- 文档里**没有**任何"作业、成绩、课程、题库"的公开 API。
- 泛雅平台的「应用中心」支持把外部系统作为一个应用挂进去（学校可自行添加教务、图书馆等系统），这和上面的"自建应用 + 链接跳转"是同一套机制。
- 未查到超星支持 **LTI 1.1/1.3**（ClassIn、雨课堂等有 LTI 插件，超星没有公开说明），如果客户坚持要 LTI，需要单独向超星确认。

> 参考：超星微服务开放平台开发文档 <http://auth.open.chaoxing.com/open/doc/list/yluywps0/zpsakobd>
> 另有大量社区逆向项目（`chaoxing-cli`、`xuexitong-cli` 等）能用 cookie 读到作业/考试/成绩，但那是**网页会话逆向**，不是官方接口。

**这意味着：**
- 身份、组织架构、消息：**可以正规对接**。
- 作业、提交、成绩：**官方没有门**。要么等超星开定制接口，要么用文件导入导出，要么走逆向（不建议）。

## 三、分级详评

### L0 外链嵌入（学习通 → 我们的系统）

- **做法**：在泛雅「应用中心」把我们的 H5 地址添加为应用；或教师在学习通课程里发一个"链接/资料"指向我们的作业页。
- **我方改造**：
  1. 前端支持 `?embed=1` 紧凑模式（隐藏侧边栏与顶栏，页面留白收窄），适配 iframe 里的小视口；
  2. 路由支持带参数直达（如 `/#/assignments?classId=1&embed=1`），落地后无需多次点击；
  3. 移动端（学习通以 App 为主）适配：侧边栏折叠、表格横向滚动、批改页上下堆叠（现有 CSS 断点已覆盖大部分，需实测）。
- **难度**：★☆☆☆☆。**工期**：1～2 人天。
- **风险**：iframe 里跨站 Cookie 的 `SameSite` 问题（见第五节，务必先改）。

### L1 学习通 OAuth 单点登录

- **授权模式**：超星开放平台不是标准 OIDC，但形态接近 OAuth2 授权码模式：
  `用户在学习通点应用 → 跳转我们地址并追加 code/state/APPID/APPKEY → 我方后端用 code + APPID + APPKEY 换 access_token → 调"获取用户信息" → 建立/绑定本地账号 → 签发我们自己的 JWT`
- **我方改造（后端）**：
  - `backend/.../config/ChaoxingOAuthClient.java`：封装 token 换取、用户信息拉取、token 刷新；
  - `backend/.../web/SsoController.java`：`GET /api/auth/sso/chaoxing/login`（生成 state 并跳转）、`GET /api/auth/sso/chaoxing/callback`（换 token、建号、签发 JWT）；
  - `domain/SsoBinding.java` + `repo/SsoBindingRepository.java`：`(provider, external_id) → user_id` 绑定表，支持一个学生既有密码登录也能 SSO；
  - `application.yml` 增加 `app.sso.chaoxing.app-id / app-key / redirect-uri / enabled`；
  - 账号策略：优先按"学号/工号"匹配已有账号，匹配不到则自动建号（角色只能给 STUDENT，教师角色需管理员确认，防越权）。
- **我方改造（前端）**：
  - 登录页加"学习通一键登录"按钮；
  - `/#/sso/callback` 路由接收 `token`，写入 store 后跳工作台；
  - 嵌入模式下不显示"退出登录"（避免把学习通会话搞乱）。
- **难度**：★★☆☆☆ 技术本身不难（就是 OAuth 客户端 + 账号绑定）。**真正的成本在审批**：企业账号注册 → 提交审核 → 拿到 APP ID/KEY，周期通常 **1～2 周**，且要说明使用单位；市场应用还要额外审核上架。
- **工期**：5～8 人天（含联调、异常态、绑定页）。
- **风险**：对方 token 有效期/刷新策略未公开细节；`state` 校验、重放、账号绑定冲突需要自己兜住；超星不同学校（泛雅私有部署）域名与配置可能不同。

### L1' 学校统一身份认证（往往更优）

- 多数高校已有 CAS / OAuth2 / LDAP 统一身份认证，学校信息中心可以给我们开一个接入方。
- **优势**：不依赖超星审核，一次接入可同时服务"从学校门户进""从学习通进"两种场景；学习通的登录本身也是接学校 CAS 的。
- **工期**：3～5 人天。**建议与 L1 并行评估，很多时候 L1' 就够了**——把两个系统都接到学校 CAS 上，用户体感就是"一次登录两边通"。

### L2 班级/学生名单同步

- **现状**：官方没有"课程/班级/选课名单"的公开 API（只有通讯录对接，偏向组织架构，不等于教学班名单）。
- **可行路径**：
  - (a) **CSV/Excel 导入**（我方 2～3 人天即可做）：教师从学习通导出名单/成绩，粘贴或上传到我们系统，按学号匹配。**推荐作为一期兜底。**
  - (b) **超星定制接口**：需商务立项，让对方开放组织/课程接口，含联调与安全评审，**周期 4～8 周起**，且不一定批。
- **难度**：★★★★☆（不是技术难，是"拿不到接口"）。

### L3 / L4 作业与成绩互通

- 官方无 API。技术上唯一替代是逆向网页接口（能读作业列表、成绩），但：
  - 依赖网页 `enc`、`ut`、时间戳等内部参数，超星一改版就废；
  - 违反平台用户协议，涉及学生个人信息批量拉取，**合规风险高**；
  - 无法获得"回写成绩"的稳定通道（学习通成绩册写入更是完全未开放）。
- **结论：明确告诉客户——"成绩自动同步回学习通"目前做不到，需要超星商务支持；一期用"我们的成绩导出 CSV → 老师手工录入学习通"过渡。**

### L5 消息推送

- 官方有「推送功能接入学习通」文档，可把"作业已布置/已批改"推成学习通消息。
- **工期**：3～5 人天，前提是 L1 的企业应用已通过审核。
- **价值**：比数据同步更能提升使用率（学生不用天天进我们系统）。

### L6 逆向接口（明确不推荐）

技术上能跑通（社区已有实现），但不作为交付方案：
- 稳定性：靠网页 `enc` 参数，超星改版即失效；
- 合规：违反用户协议，批量拉取学生信息，等保/个人信息保护审计过不去；
- 维护成本：不可预估的反复返工。

## 四、推荐实施方案（两期）

### 一期：2～3 周，我方主导，可验收

| 任务 | 端 | 人天 |
| --- | --- | --- |
| iframe/移动端紧凑模式 + 直达路由 | 前端 | 2 |
| Cookie `SameSite=None; Secure` 与嵌入态适配 | 前端/后端 | 1 |
| OAuth 客户端 + 回调 + 账号绑定/自动建号 | 后端 | 5 |
| 登录页 SSO 入口、绑定页、异常提示 | 前端 | 2 |
| 名单/成绩 CSV 导入（含模板下载、字段校验、按学号匹配） | 全栈 | 3 |
| 联调、文档、部署说明 | — | 2 |
| **合计** | | **≈15 人天（含缓冲 2～3 周）** |

**外部依赖（会导致排期卡住，必须提前启动）**：超星开放平台企业账号注册与审核（1～2 周）、`APP ID/APP KEY`、`redirect-uri` 白名单、指定使用单位的申请。

### 二期：需商务支持，单独立项

- 名单/课程同步（等超星定制接口）
- 消息推送（等应用审核通过）
- 成绩回写（基本无解，建议维持"导出 + 人工录入"）

## 五、对我方现有代码的具体影响（已核对本仓库）

> 这部分是"要改哪里"，方便直接排期。

| 位置 | 改动 |
| --- | --- |
| `frontend/src/utils/storage.js` | 目前令牌写 Cookie 用的是 `SameSite=Lax`。**在 iframe 嵌入场景下 Lax 不会随跨站请求发送**，需在嵌入模式改为 `SameSite=None; Secure`（且必须 HTTPS），否则会复现"登录后又提示未登录" |
| `frontend/src/api/index.js` | 嵌入模式下的 401 处理要更温和：不要强制跳 `#/login`（会跳出学习通 iframe），改为展示"请在学习通中重新进入" |
| `frontend/src/layouts/AppLayout.vue` | 增加紧凑/嵌入模式分支（隐藏侧栏与顶栏、隐藏退出登录） |
| `frontend/src/router/index.js` | 增加 `/#/sso/callback`、支持 `embed` 查询参数透传 |
| `frontend/src/views/Login.vue` | 增加"学习通一键登录"按钮 + SSO 失败原因展示 |
| `backend/.../domain/User.java` | 增加 `source`（LOCAL / CHAOXING / CAS）与 `externalId`（或单独建绑定表，更推荐） |
| `backend/.../config/`、`web/` | 新增 OAuth 客户端与 `/api/auth/sso/**` 控制器 |
| `backend/.../service/DataSeeder.java` | 保持不动；SSO 自动建号的账号不参与演示数据 |
| 新增 `docs/` 与导入模块 | CSV 模板、字段说明给到教务处/老师 |

**安全提醒**：SSO 自动建号必须做"学号 → 已存在账号"匹配校验，禁止凭外部返回的角色字段直接给 TEACHER 权限；所有外部回调必须校验 `state` 并做一次性消费。

## 六、风险清单

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 超星企业账号/应用审核不通过或周期长 | 一期卡在联调 | 提前 2 周提交；同时准备 L1'（学校 CAS）作为 Plan B |
| 学校是泛雅私有部署，域名/配置各校不同 | SSO 配置需按校调整 | 配置项外置（`application.yml` / 环境变量 + 后台可配） |
| iframe 跨站 Cookie 被浏览器拦截（Safari/Chrome 第三方 Cookie 限制收紧） | 嵌入态登录态丢失 | `SameSite=None; Secure` + 若被拦则退化为"新窗口打开"模式 |
| 无作业/成绩 API，客户期望落差 | 验收争议 | 在需求确认阶段书面写明"数据同步范围"，L3/L4 不承诺 |
| 逆向方案被采用 | 合规与稳定性风险 | 明确写进方案书"不采用非官方接口" |
| 学生个人信息批量流转 | 合规审计 | 最小化字段、留存期限、日志审计、签署数据处理协议 |

## 七、需要你确认的 5 个问题

1. 目标学校的学习通是**公有云版**（`*.chaoxing.com`）还是**学校私有部署的泛雅**？——决定备案与域名配置。
2. 客户真正想要的是**"在学习通里能打开我们的作业"**，还是**"作业和成绩自动同步"**？前者 2 周，后者取决于超星商务。
3. 学校是否已有**统一身份认证（CAS/OAuth2）**？如果有，优先做 L1'，可以绕开超星审核。
4. 有没有对接人可以走**超星商务/售前**？有的话 L2/L5 才有讨论意义。
5. 嵌入形态能否接受**新窗口打开**（登录态更稳），还是必须 iframe 内嵌？

---

## 八、给客户/领导的一句话版本

> 学习通的账号打通、入口嵌入可以正规实现，约 2～3 周；但"作业内容与成绩双向同步"超星目前未开放接口，需要商务定制，不建议写进交付承诺。建议一期先做"单点登录 + 嵌入 + 名单成绩文件导入"，把体验打通，数据同步等超星明确接口后再排期。
